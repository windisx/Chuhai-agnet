# 链证出海使用独立展示入口

状态：implemented
类型：feature
Owner：compose.chuhai.presentation.yaml

## 问题

通过隧道加载 Vite 开发服务的大型未压缩依赖时，展示页面的首次加载较慢。展示入口需要减少前端传输量，同时保留当前服务和后台数据。

## 决策

### 实现方案

独立展示容器使用现有 Dockerfile 的 production 阶段提供静态前端；Nginx 对静态 CSS、JavaScript 和 SVG 按客户端能力启用 gzip。`/api` 和 `/minio/public/` 继续经过已有 Vite 服务代理，保留现有认证、上传及流式响应路径。Nginx 使用 Docker DNS 重新解析 web 的地址，并将上游 Host 设置为 Vite 允许的本机地址。

展示服务默认只绑定 `127.0.0.1:25179`，不会替换原有 web、后台或数据。启动时只针对展示服务使用 `--no-deps`；未明确切换隧道前，公网仍使用原有入口。

## 替代方案

继续向公网提供 Vite 开发资源可保留热更新，但资源传输量较大；直接用生产代理替换 web 会改变请求体限制并影响现有连接。展示入口沿用 Vite 的 API 代理，保留了当前入口没有总上传请求体上限的风险。

## 后果

展示构建不会自动反映后续源码修改，需要重新构建展示镜像。真实公网速度仍受隧道与网络影响。改变既有隧道目标可能造成短暂中断或地址变化，必须先确认切换与回退方式；原开发入口保留。完整启动和回退步骤见[展示入口使用说明](../../../../展示入口使用说明.md)。

## 验证

- 在独立本机端口验证首页、登录页和现有 API 就绪接口；用户确认展示版登录和页面正常。
- 验证压缩后的入口脚本解压后与原脚本逐字节一致；入口脚本从 1,229,345 字节压缩至 383,423 字节。
- 隔离模拟上游验证两个流式路由的分块及时到达、公开对象路径和查询参数保留、21 MiB 与约 100 MiB 请求体完整转发；这些请求没有写入真实后台。
- 隔离模拟上游更换 IP 后，代理通过 Docker DNS 恢复。公网切换、真实公网速度、真实大文件上传及 cpolar 对转发头的处理尚未验证。
