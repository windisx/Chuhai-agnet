# 个人空间管理员自助注册与登录插画动效

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/registration_service.py

## 问题

登录页缺少注册入口，访客无法自行创建账号，左侧静态插画需要动态呈现。用户明确要求自助注册后获得管理员权限，以创建及上传知识库。

## 决策

### 实现方案

公开POST /api/auth/register仅接收3至20位字母开头的登录账号和8至128位密码，拒绝角色、部门和未验证手机号等额外输入。服务固定role=admin，为账号创建独立个人部门，避免加入既有业务部门。部门、用户和注册审计在同一事务提交，唯一身份冲突返回409并回滚。系统未初始化时拒绝公开注册，保留原有管理员初始化入口。

Redis原子累计连接来源IP的注册请求，每10分钟最多5次，超限返回429和Retry-After，不信任访客提供的X-Forwarded-For。登录页通过auth_api提交注册，成功后清除密码并回到登录、填入新账号；保留协议勾选与原有登录锁定、OIDC流程。

LoginDocumentMotion拥有本地SVG/CSS文件扫描、纸飞机和核查符号动效，支持暂停与减少动态效果；装饰不代表真实业务执行状态。登录页标语同步使用逗号。

## 替代方案

管理员开通账号不能满足访客直接注册使用的选择。加入默认部门会改变既有部门资源可见范围；不绑定部门则被当前get_required_user拒绝，无法直接使用。

## 后果

注册授予个人部门管理员权限，不授予superadmin；现有全局共享资源仍按原授权规则可见。注册后的部门及用户由既有超级管理员管理，无新增审批流程或数据库Schema。反向代理场景以代理连接IP计数，多个访客可能共享限额；调整代理信任和限速策略需要另行明确部署边界，不直接信任自带转发头。

## 旧注册账号升级

registration_service.promote_self_registered_users通过repository锁定旧注册审计为“访客注册普通用户账户”、角色仍为user、未删除且个人部门名称和描述均匹配的账号，仅升级这批账号并写入权限升级审计。同一事务提交，可重复执行；不按所有普通用户全量提权。前端已登录会话需要重新登录或刷新当前用户信息以更新菜单。

存量升级实际匹配1个账号，事务提交后重新读取确认role=admin且剩余候选为0。该数据库变更有审计记录；Git回退不会自动回退账号权限。

真实PG升级负向验证覆盖无旧注册审计、部门已迁移、软删除、审计不符及既有管理员，均保持原角色；审计失败回滚、成功仅升级目标1个、重复执行返回0均通过。
